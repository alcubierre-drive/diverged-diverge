Getting Started::
For an easy start with the <divERGe python interface at dvg>, install divERGe
from pip:
=== Code ===
pip install diverge-flow
============
You can further download <divERGe.tar.gz at
https://git.rwth-aachen.de/frg/diverge/-/raw/master/public/releases/v0.4/divERGe.tar.gz>
to obtain a pre-compiled copy of divERGe that additionally contains the <C
library at libdivERGe.so> and <some examples at Examples>. For all more pre-built
versions, see <releases at
https://git.rwth-aachen.de/frg/diverge/-/tree/master/public/releases>. If you
wish to <compile yourself at Compilation> to include various optimizations (<MPI
at Compilation-MPI>, <CUDA at Compilation-CUDA>, ...), you can do so by cloning
the <git repository at https://git.rwth-aachen.de/frg/diverge.git> and following
the <build instructions at Compilation>. Moreover, environment variables can be
used to change the number of threads for different components, see
<Runtime-Tuning>.

Usage::
The <C library at libdivERGe.so> represents the centrum of divERGe. Python
specific library features (e.g. the <autoflow at dvg.autoflow> function) are
documented <here at dvg>. For reading the output files, see <diverge.output at
dvg-output>.

We now continue with the example: On a not-too-old Linux machine (GLIBC >=
2.17), extract the tar.gz file and use a python3 interpreter to execute <the
simple example at
https://git.rwth-aachen.de/frg/diverge/-/blob/master/examples/python/simple.py>.
Alternatively, use the <hyperlink at
https://git.rwth-aachen.de/frg/diverge/-/blob/master/examples/python/simple.py>
to download the simple example.
=== Code ===
mkdir divERGe
tar -C divERGe -xvf divERGe.tar.gz
cd divERGe
python3 examples/simple.py
============

(see simple_example_model.png)

Troubleshooting::
If the pip installation fails, you can navigate to the folder where you
extracted <diverge.tar.gz at
https://git.rwth-aachen.de/frg/diverge/-/raw/master/public/releases/v0.4/divERGe.tar.gz>
and execute
=== Code ===
python3 setup.py install
============

Congratulations::
You've just managed to do your first FRG simulation of a square lattice Hubbard
model that displays $d$-wave superconductivity! Now let's take a look at the
output:

Besides the compilation status of the library (first line) and some logging
information (prefixed with *[divERGe:logname]*), the on-line output contains
information on chosen defaults and other miscellaneous information (prefixed
with #): We observe that two files have been written: model.dvg (containing
everything set in the <diverge_model_t>) and post.dvg (written by
<diverge_postprocess_and_write at
diverge_postprocess_conf_t.diverge_postprocess_and_write>). To read the .dvg
files, we strongly suggest to use the function provided in the python library
<diverge.output at dvg-output>. Apart from the output files, the values for the
scale and integration of the flow equations as table with entries Lambda,
dLambda, Lp, Lm, dP, dC, dD, V are printed This output can be conveniently piped
to a file to obtain a flow data file for further processing. Instead of
=== Code ===
python3 examples/simple.py
============
you can call
=== Code ===
python3 examples/simple.py > flow.dat
============
to obtain three files as output: model.dvg, post.dvg, and flow.dat (with the
flow information). The columns in flow.dat correspond to:

Lambda - the current scale
dLambda - the step size
Lp - the particle particle loop maximum
Lm - the particle hole loop maximum
dP - the differential (for grid and patch) or absolute (for tu) channel maximum
     in the particle particle channel
dC - the differential (for grid and patch) or absolute (for tu) channel maximum
     in the crossed particle hole channel
dD - the differential (for grid and patch) or absolute (for tu) channel maximum
     in the direct particle hole channel
V - the absolute maximum element of the vertex (for grid/patch) or maximum of
    the channel maxima (tu)
